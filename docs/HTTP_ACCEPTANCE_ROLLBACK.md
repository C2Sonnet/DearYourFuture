## CLIの使用（運用者所有の隔離環境に限る）
Python 3.8+、標準ライブラリのみ。HTTPは127.0.0.1または::1限定、HTTPSは証明書検証を有効にした既定SSLコンテキストを使用。リダイレクト非追従。外部公開前にネットワーク制限された専用環境で実施。POST/PUTは閲覧専用サイトの405拒否確認のみ、他サイトに実行しない。実際に配布する版の独立承認済みZIP SHA256と、監査済み隔離storageのtar.gz SHA256を指定（HTTP応答から採取して期待値にしない）。

```sh
python3 accept_http.py https://YOUR-ISOLATED-HOST --zip-sha256 EXPECTED_ZIP_SHA256 --tar-sha256 EXPECTED_TAR_SHA256 --confirm-owned-isolated > acceptance.json
```

終了コード0=HTTP全合格、1=検査失敗、2=引数不備。JSONには経路・ステータス・結果のみを記録。レスポンス本文は保存しない。38項目はHTML12、静的資産5、画像1、配布2、HEAD2、拒否16。HTMLはCSP・nosniff・識別ID、ダウンロードは添付とSHA256、静的資産は非空を確認。完全なヘッダー監査、PHP-FPM識別、画像形式、全資産ハッシュ、視覚・操作確認は別試験。通信タイムアウトは各リクエスト10秒。合格してもrelease_gate=HOLD。

## 本番候補の切替・ロールバック（手順案、実環境未検証）
1. 対象専用ドメイン・DocumentRoot・PHP-FPMユーザーを確認。既存就活支援サイトとDBを変更しない。公開権利・個人情報の承認を受けるまでネットワーク隔離。
2. 更新停止後、旧アプリ・設定・Rewrite・storageを保全する。storage_admin.py audit、backup、verifyを実施。アプリZIP・設定のチェックサムと対応版を別記録。旧環境と同一ストレージを新環境へ共有しない。
3. 新しい独立ディレクトリへ配布ZIPを検証・展開、必要ならrehearse_legacy.pyまたはstorage_admin.py restoreで隔離復元。実行ユーザーの読取りと書込み拒否を確認。公開ルートはpublic/のみ。新規設定は既存環境に上書きしない。
4. nginx -t、隔離HTTP受入、実PHP-FPM/HTTPS、UI、DB、権利審査を完了。運用者が全項目承認した場合のみ計画停止中に切替。新環境の公開ソースと旧環境を混在させない。
5. HTTP失敗・503連続・ハッシュ不一致・権限異常・情報漏洩の疑い・DB不整合なら切替を中止、一般アクセスを遮断。状態やログを保全し、旧版のアプリ＋対応storage＋設定の組を検証済み状態へ戻す。旧環境にも安全性の疑いがあれば公開停止を維持。ロックを強制削除しない。新環境で登録した版は隔離保全し、自動逆同期しない。
6. 旧設定のnginx -t、既存運用手順によるreload、受入CLI（旧版の期待ハッシュ）・ログ・権限を確認。成功し承認された場合のみアクセス再開。失敗なら公開停止のまま原因調査。

DB切替は未実装のため、この手順はファイルベース運用に限定。MySQL正本化後にはDBバックアップと世代同期を別途受入する必要がある。実際の本番操作・共有設定変更・他サブプロジェクト変更なし。NginxはRewrite断片のみ同梱、server全体設定なし。
