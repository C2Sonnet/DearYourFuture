# MySQL正本読み取り候補 v0.13.0
2026-11-24 / 内部実装・外部作業未開始

- `CP_REPOSITORY_MODE` 未設定または `files` は現行方式。`mysql` を明示すると `MysqlReadModel` を使用。不正値や接続失敗・不整合は503、ファイル方式への自動フォールバックなし。設定切替は運用者の外部受入後のみ。既存の公開環境には適用しない。
- 専用ローカルDB `codepublication_*` のみ。`CP_READER_DATABASE`, `CP_READER_HOST`, `CP_READER_PORT`, `CP_READER_USER`, `CP_READER_PASSWORD` はWeb実行環境で設定する。パスワードをZIPやログに保存しない。移行・同期用 `CP_MYSQL_*` と別の読み取り専用アカウント（SELECTのみ）を使用。実権限の付与・試験は外部工程。
- DBはREPEATABLE READ/READ ONLYトランザクション、ストレージは既存publish.mutexの非ブロッキング共有ロックをリクエスト中保持。ロック競合・未完了ジャーナルは拒否。1リクエスト内で検証済みカタログ・ファイル索引を再利用。
- schema_migrationsの既知チェックサム、publication_state READY・世代・最新ID・カタログSHA、全リリース行の順序・親・メタデータ・登録時刻・ZIP SHAを検証。DBから得たメタデータを返し、比較対象のファイル側メタデータと一致を要求。旧形式のハッシュなしメタデータは隔離再登録が必要。
- 閲覧対象版のファイルDB行全件の件数・パスハッシュ・ファイルSHA・サイズ・最終変更版を検証。DB側の値と照合済みファイル索引（表示用の行数・text等）を組み合わせる。ZIP/tar、ファイル本体・差分は既存のハッシュ検証を継承。全版の全ファイル本体を毎リクエスト監査するわけではない。全体監査はmysql_plan.py。
- DB更新の二相処理は未実装。ファイル更新直後から同期完了まではハッシュ不一致で閲覧停止。同期が失敗しても自動復旧・自動切替・旧版上書きはしない。DB障害時に秘密情報を含む例外をHTTPやアプリログに出さない。
- 現在の実DB検証は未実施。オフラインでは実publisherで作成した2版とSQL行の模擬値に対して同じ照合関数を実行。HTTPはファイルモード正常、MySQL/不正モードで503を検証。模擬データが実DB実行を意味しない。PDO MySQL、実DB、FPMは利用できない。実DBのDDL・トランザクション・権限・同期・復旧は外部受入待ち。
